# Checklist — cadrage

À remplir avant la première ligne de code.

## Produit

- [ ] Nom et slug choisis (pas de marque tierce comme identité).
- [ ] Utilisateur cible décrit en une phrase.
- [ ] Problème actuel explicite (temps, coût, fragilité).
- [ ] Promesse en une phrase.
- [ ] MVP limité à 3–5 fonctions.
- [ ] Hors-scope écrit noir sur blanc.
- [ ] Critère de succès mesurable.

## Technique

- [ ] Plateformes visées et formats de distribution.
- [ ] Format d'entrée et de sortie.
- [ ] Volume de données réaliste (Mo/Go, temps réel ?).
- [ ] Besoin GPU / audio / codec identifié.
- [ ] Mode offline ou réseau tranché.
- [ ] Stratégie de persistance choisie.
- [ ] Besoin d'undo tranché.
- [ ] Framework UI choisi et justifié.

## Légal et assets

- [ ] Licence du code choisie (`MIT OR Apache-2.0` par défaut).
- [ ] Disclaimer d'indépendance rédigé.
- [ ] Licence de chaque dépendance lourde vérifiée.
- [ ] Licence des assets/samples vérifiée.
- [ ] Aucun asset propriétaire prévu dans le dépôt.

## Gate

- [ ] Brief relu par une deuxième personne ou par l'utilisateur.
- [ ] Maquette filaire des 3 écrans principaux.
- [ ] Liste des risques principaux (voir DOMAINS.md).
- [ ] Prochaine action atomique identifiée.
